# Схема kp.json

Все секции, кроме `meta`, `seller`, `client` и `cover`, опциональны — пустые или отсутствующие скрипт пропускает. Порядок секций в PDF фиксирован скриптом, порядок ключей в JSON значения не имеет.

Плейсхолдеры для неизвестных данных — строго `[[УТОЧНИТЬ: что вписать]]`. Они подсвечиваются красным в PDF/DOCX и собираются в отчёт после сборки.

```
meta
  number          "КП-2026-014"                номер документа
  date            "17 августа 2026"            дата
  valid_until     "31 августа 2026"            до какого числа действует
  language        "ru" | "en"                  влияет на подписи блоков; по умолчанию ru
  currency        "₸" | "₽" | "$" | "€"        только для подписей, цены пиши строками

seller
  name            "TechFlow"                   как называть компанию в тексте
  legal_name      "ТОО «ТехФлоу»"              для футера
  tagline         "Автоматизация складского учёта"
  site            "techflow.kz"
  accent          "#1B4DFF"                    фирменный цвет; по умолчанию тёмно-синий
  manager         { name, role, phone, email }  конкретный человек, а не общий ящик

client
  company         "Sulpak"
  contact_name    "Ксения Ли"                  может отсутствовать
  contact_role    "Директор по операциям"
  city            "Алматы"

cover
  headline        главный заголовок — выгода клиента, не название документа
  subheadline     одно предложение: для кого и в каком объёме

greeting          абзац-обращение с привязкой к реальному разговору

situation
  intro           1-2 предложения о ситуации
  points[]        { title, text }              3-4 факта о текущем положении
  cost            строка про цену бездействия (опционально)
  sources[]       { fact, source }             откуда факты; печатается мелким шрифтом сноской

solution
  intro           опционально
  blocks[]        { title, text, result }      3-5 блоков; result — измеримый эффект

scope
  included[]      строки — что входит
  excluded[]      строки — что не входит

stages
  items[]         { n, title, duration, actions, client_input, deliverable }
  total           "6 недель от подписания"
  payment         "40% старт / 40% после этапа 2 / 20% приёмка"

pricing
  intro           опционально
  options[]       { name, price, price_note, for_whom, includes[], recommended:bool }
  terms[]         строки: НДС, срок действия цены, что не включено
  note            опционально

economics                                      блок окупаемости; пропускается, если нет данных
  title           "Экономика проекта"
  rows[]          { label, value }
  conclusion      вывод одной строкой

proof
  cases[]         { client, task, result, quote }   quote опционально
  facts[]         строки: проверяемые факты о компании

faq
  items[]         { q, a }                     3-5 пар

cta
  text            1-2 предложения
  action          одно конкретное действие
  link            опционально: ссылка на календарь/форму

footer_note       мелким шрифтом внизу: реквизиты, оговорки
```

## Минимальный валидный пример

```json
{
  "meta": { "number": "КП-2026-001", "date": "17 августа 2026" },
  "seller": { "name": "TechFlow", "manager": { "name": "Айдын С.", "email": "a@techflow.kz" } },
  "client": { "company": "Ромашка" },
  "cover": { "headline": "Сводка по 4 складам к 9 утра вместо ручной выгрузки к 5 числу" },
  "cta": { "text": "Готовы начать с бесплатного аудита.", "action": "Ответьте на письмо — пришлём план первой недели" }
}
```

Полный заполненный пример нужного уровня конкретики — `example-kp.json`.
