# Схема processed.json

Обязательна только секция `tickets`. Всё остальное улучшает отчёт, но не ломает сборку.

```
meta
  company          "ДомПлюс"
  source           "выгрузка tickets.csv" | "почта support@" | "Intercom"
  run_at           "2026-08-20 10:30"
  period           "19 авг 22:00 — 20 авг 10:15"   какой отрезок разобран
  policy_version   какой версией политики руководствовались

tickets[]
  id, created, channel, customer, email, subject, text   из загрузчика, без изменений

  topic        "Доставка" | "Возврат" | …        тема; по ней строится фильтр
  type         "вопрос" | "проблема" | "жалоба" | "запрос на покупку" | "спам"
  urgency      "low" | "normal" | "high"
  sentiment    "positive" | "neutral" | "negative"

  decision     "answer"              ответ готов, оснований достаточно
               "answer_with_caveat"  отвечаем, но с оговоркой или частично
               "escalate"            решает человек
               "no_reply"            спам и автоматические рассылки — без ответа,
                                     в статистику автоматизации не считаются

  confidence   "high" | "medium" | "low"
               low поднимает обращение наверх отчёта наравне с эскалациями.
               У эскалации относится к промежуточному ответу клиенту, а не к решению передать человеку

  draft        текст ответа клиенту. Заполняется и при эскалации —
               тогда это промежуточный ответ: «принял, передал, вернёмся тогда-то».
               Клиент не должен ждать в тишине, пока кейс идёт к менеджеру.

  kb_refs[]    { title, section } — разделы базы, на которых стоит ответ.
               Пустой список при decision != "escalate" — сигнал, что ответ
               не привязан к базе; скрипт про это предупредит.

  escalation   { reason, to, what, priority, brief }
               reason — суть одной фразой; to — кому; what — что решить;
               priority — с обоснованием; brief — контекст, которого нет в самом обращении

  kb_gap       чего не хватило в базе. Собирается в отдельный блок отчёта —
               это план, как поднять долю автоматических ответов к следующему прогону

summary
  notes        1-2 фразы о прогоне
  kb_gaps[]    опционально: сводный список; если не задан, собирается из тикетов
```

## Минимальный валидный пример

```json
{
  "meta": { "company": "ДомПлюс", "run_at": "2026-08-20 10:30" },
  "tickets": [
    {
      "id": "W-2043", "customer": "Диас", "text": "Доставка в Караганду сколько идёт?",
      "topic": "Доставка", "type": "вопрос", "urgency": "normal",
      "decision": "answer", "confidence": "high",
      "draft": "Диас, здравствуйте. В Караганду — 3-7 рабочих дней…",
      "kb_refs": [{ "title": "Доставка", "section": "Сроки" }]
    }
  ]
}
```

Полный пример нужного уровня — `example-processed.json`, демонстрационные входные данные — `demo/kb.md` и `demo/tickets.csv`.
